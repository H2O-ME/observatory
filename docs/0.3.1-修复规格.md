# 0.3.1 修复规格（唯一事实来源）

状态：**实施中**。本文档映射 0.3.1 的全部修复项（F0–F66），是验收断言与代码注释里
`0.3.1`/`Fxx` 标注的对照表。0.3.0 规格见 [0.3.0-重构规格.md](0.3.0-重构规格.md)（历史规格，
顶部有 0.3.1 变更注记）。

## 0. 决策前提（已拍板）

1. **legacy 兼容层整体删除**（原计划 0.4 提前）：`server/observatory/legacy/`、共享注册码
   `OBS_ENROLL_CODE`、CLI `enroll-code` 子命令、`migrate-from-legacy.sh`、
   `fix-nginx-dual-track.py`、0.2.10 协议回放测试全部移除。现网设备已全部 0.3.0。
2. **`MIN_SELF_UPDATE_VERSION = "0.3.0"`**：0.3.0 是首个具备 sha256 校验 + 预检 + 回滚的
   自更新版本；更旧的设备只能重装。
3. **自动更新首跳**：现网 0.3.0 受控端的 offer 接收逻辑完整，服务端（F1）补上下发方后，
   设备在下次重连的 welcome 中收到 update_offer **自动升级到 0.3.1**；控制台手动命令为兜底。
4. 不做：多 worker/横向扩展（单进程内存态是架构约束）、DB 已有列删除、新协议版本（仍 v3）。

## 4. 已知未尽项（记录，不阻塞发版）

- **QueuePool**：NullPool→QueuePool 的迁移因 Python 3.14 aiosqlite dispose 挂起风险推迟，
  PRAGMA 拆分已消掉其主要成本。
- **retention 孤儿扫描增量花**：按 day/hour 目录桶扫描未实施（当前全表 SELECT + 全盘 stat
  仍在，量级见审计）；dangling 已游标轮转。
- **缩略图二次解码**：normalize 复用 PIL 对象未实施（每帧多一次解码，~10-40ms）。
- **前端文件传输**：分片重试/断点续传/大文件分批合成未实施（F42 部分遗留）。
- **unwrap data 兼容分支**：保留（F7 后可删，但需逐端点核对信封化完成度）。
- **真机验证清单**（发布门禁，见 README/部署.md §12）：service 模式管道身份校验
  （win_smoke）、125% DPI 点击精度、删除设备后 agent 收 410 停连、断网重连后 outbox 帧
  不丢、升级失败自动回滚。

## 5. 发布流程

1. `tools/set_version.py --bump` → 0.3.1；CI 全绿（含 F60/F61 修复后的门禁）；tag v0.3.1。
2. 生产 `deploy/update.sh`（自带备份 + 回滚）。
3. 现网 0.3.0 受控端经 F1 的 update_offer **自动升级**；手动批量命令兜底。
4. `tools/check_deployment.py --password-stdin`（F64）全过 + 三项人工验收。
