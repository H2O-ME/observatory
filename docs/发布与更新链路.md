# 发布与更新链路（0.3.6 起）

> 本文是 **代码发布 / 生产部署 / 受控端安装包上线** 的唯一操作说明。
> 旧的「SSH 上去手工 `update.sh`」仍可用，但默认链路已经自动化。

## 1. 拓扑

```
本地开发机
  │  git push origin main / v<VERSION>
  ▼
GitHub 仓库
  ├─ main ───────────────┐
  └─ v<VERSION> tag       │
        │                 │
        ▼                 │
  GitHub Actions           │
  - 质量门禁（version/lint/server/contract/acceptance/webui/deploy-static）
  - Windows runner 构建受控端 zip
  - 强推 agent-dist 分支（仅 tag）
        │                 │
        ▼                 ▼
部署服务器（/opt/observatory）
  observatory-auto-update.timer（每 2 分钟）
  ├─ git fetch origin main + agent-dist（只读 deploy key）
  ├─ main 有运行时变化 → deploy/update.sh → 构建镜像、切换容器、健康检查/回滚
  ├─ main 只有文档/CI/部署脚本/agent 源码 → git merge --ff-only（不重建）
  └─ agent-dist 出现同 VERSION → fetch-agent-package.sh → 校验 sha256 → 登记安装包
        │
        ▼
  在线受控端下一次心跳拿到 update_offer → 自行升级（SYSTEM，无 UAC）
```

服务器**不保存 GitHub PAT**；GitHub 访问使用一把只在 `/opt/observatory` 可读的
**只读 deploy key**（`~/.ssh/id_ed25519_observatory`），`origin` 指向 SSH alias：

```bash
git -C /opt/observatory remote -v
# origin  git@github-observatory:H2O-ME/observatory.git (fetch)
# origin  git@github-observatory:H2O-ME/observatory.git (push)
```

## 2. 本地发版（服务端 + WebUI）

```bash
# 1) 版本号唯一来源：VERSION
python tools/set_version.py --bump       # 例：0.3.6 -> 0.3.7
python tools/set_version.py --check      # 必须一致

# 2) 提交并推送 main
git add -A
git commit -m "release: 0.3.7"
git push origin main

# 3) 打 tag 触发受控端构建（只有 tag 会发布 agent-dist）
git tag -a v0.3.7 -m "Observatory 0.3.7"
git push origin v0.3.7
```

推送后：

1. `main` 被服务器 timer 在 ≤2 分钟内发现 → 自动部署服务端/WebUI；
2. tag 触发 GitHub Actions：
   - 所有质量门禁通过后才构建 Windows 受控端；
   - 产物 `observatory-agent-0.3.7.zip` 被推送到 `agent-dist` 单提交分支；
   - 生成 GitHub Release；
3. 服务器下一轮发现 `agent-dist/VERSION == 0.3.7` → 取回、校验 sha256、登记；
4. 低于 0.3.7 的在线设备在下一次心跳自动升级。

> 只推 `main` 不推 tag：服务端/WebUI 会更新，**受控端包不会变化**（安全约束）。

## 3. 服务器自动任务

安装（每台服务器一次）：

```bash
sudo bash /opt/observatory/deploy/install-auto-update.sh
systemctl list-timers observatory-auto-update.timer
```

运行与日志：

```bash
systemctl status observatory-auto-update.timer
tail -f /var/log/observatory-auto-update.log
journalctl -u observatory-auto-update.service -n 120 --no-pager
journalctl -u observatory-auto-update.service -f
```

行为细节：

| 变更类型 | 自动动作 |
| --- | --- |
| `server/`、`webui/src`、`webui/package*.json`、`VERSION`、`webui/index.html` 等运行时文件 | `deploy/update.sh`：构建 `observatory/api:<VERSION>`、切容器、健康检查、失败回滚 |
| 只有 `docs/`、`README.md`、`.github/`、`tests/`、`tools/`、`agent/`、`deploy/`（除 compose）、`webui/DESIGN_SYSTEM.md` | `git merge --ff-only`，不重建镜像 |
| `deploy/docker-compose.yml` | 走 `update.sh`（应用 compose 配置） |
| `agent-dist` 出现同 `VERSION` 包 | `fetch-agent-package.sh`：导出 zip → `/data/tmp` → `package-add` 落库 |
| 无新提交、包已登记 | 空转退出（无操作） |

- 自动部署默认 `SKIP_BACKUP=1`（不生成 200MB+ 数据卷备份；用户明确要求不保留备份）。
- 手工执行 `sudo bash deploy/update.sh` 仍默认备份，可用 `SKIP_BACKUP=1` 跳过。
- 自动部署失败由 `update.sh` 自动回滚代码 + 旧镜像；日志在 `backups/update.log`。

暂停/恢复自动更新：

```bash
sudo systemctl disable --now observatory-auto-update.timer   # 暂停
sudo systemctl enable --now observatory-auto-update.timer    # 恢复
```

## 4. 手工兜底

```bash
# 单次检查并部署（和 timer 走同一条逻辑）
sudo bash /opt/observatory/deploy/auto-update.sh

# 只拉代码/包，不构建
cd /opt/observatory
git fetch origin main --tags
git merge --ff-only origin/main
sudo bash deploy/fetch-agent-package.sh
```

## 5. 发布验证

```bash
curl -fsSk https://control.tianhw.top/api/v1/health
curl -fsSk https://control.tianhw.top/api/v1/version
docker ps --format '{{.Names}} {{.Image}} {{.Status}}' | grep observatory
docker exec observatory-api python -c \
  "import sqlite3;c=sqlite3.connect('/data/observatory.db');print(c.execute('select version,filename from packages order by created_at_ms desc limit 3').fetchall())"
curl -fsSk https://control.tianhw.top/ | grep -o 'index-[A-Za-z0-9_-]*\.js' | head -1
```

要求：

- `/api/v1/health` `ok:true` 且 `version` 等于 `VERSION`；
- 容器 `healthy`；
- `packages` 最新版本等于 `VERSION`；
- HTML 引用的 JS 哈希与本次构建一致。

## 6. 凭据与安全

- 服务器 deploy key **只读**，只允许拉取仓库；不要给它写权限。
- 不要把 GitHub PAT 写进 `git remote`、`.env`、脚本或日志；CI 发布 agent-dist 使用
  GitHub Actions 自动注入的 `GITHUB_TOKEN`。
- 本地推送涉及 `.github/workflows/**` 时，触发推送的 token 需要 `workflow` scope；
  用完建议作废/轮换。
- 自动更新没有额外回调端口：服务器主动出站拉取，不需要开放 webhook。

## 7. 排障

| 现象 | 检查 |
| --- | --- |
| push 后 2 分钟没更新 | `journalctl -u observatory-auto-update.service -n 80`，看 fetch 是否报错 |
| 反复重建同一版本 | 提交里是否总含运行时文件；`git diff --name-only` 验证 |
| 服务器拉不到 GitHub | `ssh -T git@github-observatory`、deploy key 是否仍在仓库 Settings → Deploy keys |
| agent-dist 已更新但控制台没包 | `git show origin/agent-dist:VERSION`、`fetch-agent-package.sh` 输出、`/data/packages` 权限 |
| 构建/启动失败 | `tail -n 120 /opt/observatory/backups/update.log`；`upgrade-*` 目录保留旧 commit/镜像记录 |
| 想人工阻止自动部署 | `systemctl disable --now observatory-auto-update.timer` |
