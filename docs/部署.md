# 部署

本文覆盖：服务器准备、域名与证书、容器、日常更新、备份恢复、故障排查。

## 1. 前置条件

* 一台 Linux 服务器（Debian/Ubuntu），root 或 sudo
* 两个域名的 A 记录都指向该服务器：
  * `control.tianhw.top` —— 控制台 + 受控端
  * `observatory.123423.xyz` —— **仅**受控端（安装脚本与设备接口）
* 放行 80/443（证书申请与访问）；8443 只在回环监听，不需要对外

两个域名的分工是硬约束：受控端接入互为备份，控制台只认 `control.tianhw.top`。
这个规则在两层实现——nginx 与 `server/observatory/hostsplit.py`。后者是必须的，因为 `Host` 头可以伪造。

## 2. 首次部署

```bash
sudo REPO_URL=git@github.com:<you>/observatory.git \
     CERTBOT_EMAIL=you@example.com \
     bash deploy/setup.sh
```

脚本会：

1. 安装 docker / compose / nginx / certbot（已装则跳过）
2. 克隆仓库到 `/opt/observatory`
3. 生成 `server/.env`（随机 `OBS_SECRET_KEY`、`OBS_ADMIN_PASSWORD`、`OBS_ENROLL_CODE`），并打印管理员密码与注册码
4. 用 standalone 方式为两个域名申请证书，并软链到 `/opt/observatory/certs/`
5. 安装 nginx 站点、构建镜像、启动容器、等待健康检查

结束时请立刻记录 `server/.env` 里的 **管理员密码** 与 **注册码**。

> 再次运行 `setup.sh` 是安全的：已有 `.env`、证书、数据卷都不会被覆盖。

## 3. 结构

```
/opt/observatory/
  server/.env                密钥与配置（chmod 600）
  certs/server.crt|key       指向 /etc/letsencrypt/live/...
  deploy/docker-compose.yml
compose 资源：
  container  observatory-api
  volume     observatory-data   (/data: 数据库、画面、缩略图、安装包)
```

镜像里同时构建控制台前端，启动时按版本号发布到 `/data/webui`（见 `main.py: sync_webui`）。
所以"升级服务端"天然带着前端升级，不会出现前后端版本不一致。

### 从旧版本迁移（已有一台在跑的主机）

```bash
sudo bash deploy/migrate-from-legacy.sh
```

脚本会：配置 GitHub 部署密钥 → 克隆到 `/opt/observatory` → 复用旧证书 →
生成 `server/.env`（复用旧 ADMIN_PASSWORD / SECRET_KEY，新生成注册码）→
停掉旧容器（**旧数据目录原样保留**）→ 构建并启动新栈 → 等待健康检查。

回滚：

```bash
docker compose -p <旧项目名> -f /opt/<旧目录>/docker-compose.yml up -d
```

如果主机上还有 nginx 做域名分流，跑一次 `deploy/fix-nginx-dual-track.py`：
它把两个域名的规则改成"受控端接口两边都通，控制台只在 control 域名"，
并给受控端域名补上 WebSocket 升级头。脚本会先 `nginx -t` 再 reload，失败不生效。

## 4. 域名策略

| 路径 | control.tianhw.top | observatory.123423.xyz |
| --- | --- | --- |
| `/`（控制台） | ✅ | ❌ 404 提示 |
| `/assets/*` | ✅ | ❌ |
| `/api/v1/auth/*` | ✅ | ❌ |
| `/api/v1/devices*` | ✅ | ❌ |
| `/api/v1/settings` `/audit` `/updates` `/system` `/ws` | ✅ | ❌ |
| `/api/v1/agent/*` | ✅ | ✅ |
| `/api/v1/public/*` | ✅ | ✅ |
| `/api/v1/health` `/api/v1/version` | ✅ | ✅ |
| `/install.ps1` | ✅ | ✅ |

受控端注册时拿到的是**两个地址的有序列表**（`OBS_PUBLIC_BASE_URLS`）：

```json
{"base_urls": ["https://control.tianhw.top", "https://observatory.123423.xyz"]}
```

任意一个连不上就自动切下一个；恢复后按探测结果重新排序。

## 5. 日常更新

```bash
sudo bash deploy/update.sh
```

流程：stash 本地改动 → `git pull --ff-only` → 重建镜像（含前端）→ `up -d` → 等待健康检查 →
把 `agent/dist/observatory-agent-*.zip` 登记为可更新版本。

脚本如果发现自己被这次 pull 更新了，会带上 `OBS_UPDATE_REEXEC=1` 重新执行一次，
否则 bash 会继续跑内存里的旧版本（这个坑踩过一次）。

受控端**不需要重新安装**：下一次心跳拿到新版本号后自行下载、校验 SHA-256、等待服务停止、
原子替换目录并重启。

## 5.1 上线体检

部署完、以及每次更新后，跑一次：

```bash
python tools/check_deployment.py --password '<控制台密码>' --code '<注册码>'
```

它从公网按真实客户端路径验证 28 项：两个域名的健康检查与版本一致性、控制台只在
`control` 域名、两侧都能取安装脚本与安装包、安装包 sha256 与服务器一致、控制台登录、
受控端注册与 **WebSocket 升级**（证明 nginx 的 upgrade 头没丢）、体检设备可删除。

## 6. 证书续期

```bash
# 建议加一条 cron
0 4 * * * root bash /opt/observatory/deploy/renew-certs.sh >/dev/null 2>&1
```

`renew-certs.sh` 只在证书真的续期后才重启容器（容器启动时读取证书）。

## 7. 备份与恢复

```bash
sudo bash deploy/backup.sh                 # 备份数据库（在线 backup API）+ 数据卷 + 证书
sudo bash deploy/restore.sh <备份.tar.gz>  # 会要求输入 RESTORE 确认
```

备份包含：SQLite 数据库、`frames/`、`thumbs/`、`packages/`。
数据库里存的是相对路径，所以数据卷可以整体搬走。

## 8. 配置项

全部以 `OBS_` 开头，写在 `server/.env`（参考 `server/.env.example`）。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `OBS_SECRET_KEY` | 必填 | JWT 与设备令牌哈希的密钥，更换后所有会话失效 |
| `OBS_ADMIN_PASSWORD` | 必填 | 初始管理员密码（在控制台改后以数据库中的哈希为准） |
| `OBS_ENROLL_CODE` | 空=禁用注册 | 安装脚本与受控端注册使用 |
| `OBS_DATA_DIR` | `/data` | 数据目录 |
| `OBS_CONSOLE_HOST` | `control.tianhw.top` | 唯一允许控制台的域名 |
| `OBS_AGENT_HOSTS` | 两个域名 | 允许受控端接口的域名（逗号分隔） |
| `OBS_PUBLIC_BASE_URLS` | 两个 https | 下发给受控端的地址列表 |
| `OBS_SESSION_TTL_MINUTES` | 720 | 控制台会话有效期 |
| `OBS_AGENT_OFFLINE_AFTER_S` | 120 | 判定离线的静默时长 |

运行时业务参数（采集间隔、保留天数、配额等）在控制台「设置」页修改，不需要重启。

## 9. 故障排查

```bash
docker compose --env-file server/.env logs -f --tail=100     # 应用日志
docker exec -it observatory-api python -m observatory.cli version
curl -sk https://127.0.0.1:8443/api/v1/health
curl -sk https://control.tianhw.top/api/v1/health            # 控制台域名
curl -sk https://observatory.123423.xyz/api/v1/health        # 受控端域名
nginx -t && systemctl reload nginx
```

常见问题：

* **控制台能开但所有接口 404**：访问的是受控端域名。控制台只认 `control.tianhw.top`。
* **受控端注册失败 403**：`OBS_ENROLL_CODE` 为空或与安装命令里的不一致。
* **受控端一直"仅轮询"**：WebSocket 被中间设备阻断。服务器是必须的：实时控制只在 WS 下可用。
  检查 nginx 的 `Upgrade` / `Connection` 头，以及是否有 CDN 只允许 HTTP/1.1。
* **设备显示离线但仍有画面**：画面是历史数据；`presence.reason` 会说明最后上报距今多久。
* **上传安装包报 400**：文件名必须含版本号，例如 `observatory-agent-0.2.1.zip`。
* **容器启动即退出**：多半是 `/certs/server.crt` 不存在。运行 `deploy/setup.sh` 或检查软链。
