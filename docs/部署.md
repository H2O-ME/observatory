# 部署（Observatory 0.3.0）

覆盖：服务器准备、首次部署、网络拓扑、日常更新与回滚、证书、备份恢复、安装令牌、配置、迁移、排障。

> 本文以 0.3.0 仓库脚本为准；与旧版文档冲突之处一律以本文与
> [`docs/0.3.0-重构规格.md`](0.3.0-重构规格.md) 为准。

## 1. 前置条件

* 一台 Linux 服务器（**Debian 或 Ubuntu**，root/sudo；脚本用 `apt` + `systemd`）。
* 两个域名的 A/AAAA 记录都指向该服务器：
  * `control.tianhw.top` —— 控制台 + 受控端接口；
  * `observatory.123423.xyz` —— 仅受控端接口与安装脚本（不提供控制台）。
  域名可用 `CONSOLE_HOST` / `AGENT_HOST` 覆盖，但需要同步修改 `.env` 与 DNS。
* 放行 80/443（ACME + 访问）。8443 **默认只绑回环**，不需要对外。
* 出站可访问 Docker Hub、Let's Encrypt、GitHub（拉代码/取受控端包）。

## 2. 首次部署

```bash
sudo REPO_URL=git@github.com:<you>/observatory.git \
     CERTBOT_EMAIL=you@example.com \
     bash deploy/setup.sh
```

常用环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `APP_DIR` | `/opt/observatory` | 部署目录 |
| `REPO_URL` | 空（用当前目录） | 无本地仓库时克隆地址 |
| `CONSOLE_HOST` | `control.tianhw.top` | 控制台域名 |
| `AGENT_HOST` | `observatory.123423.xyz` | 受控端域名 |
| `CERT_NAME` | `observatory` | certbot lineage 名（单张双域名证书） |
| `CERTBOT_EMAIL` | 必填（首次） | ACME 账户邮箱 |
| `ACME_WEBROOT` | `/var/www/certbot` | webroot 续期路径 |
| `OBS_UID` | `10001` | 容器运行 UID；证书属主会同步为该 UID |

脚本步骤（可重复运行；已有 `.env`/证书/数据卷不会被覆盖）：

1. **校验**：root、域名格式、两域名不同。
2. **Docker**：已装 docker+compose 则跳过；否则按发行版选择官方源
   （Debian → `download.docker.com/linux/debian`，Ubuntu → `.../linux/ubuntu`；衍生发行版可用
   `DOCKER_DISTRO=debian|ubuntu` 覆盖）。
3. **nginx + certbot**：分别检测是否安装（旧版只看 nginx，会漏装 certbot）。
4. **代码与 `server/.env`**：随机生成 `OBS_SECRET_KEY` / `OBS_ADMIN_PASSWORD` /
   `OBS_ENROLL_CODE`，并写入 `OBS_BIND_ADDR=127.0.0.1`、
   `OBS_TRUST_FORWARDED_FOR=true`、`OBS_UID` 与资源限制变量（旧 `.env` 缺这些键时会追加默认值）。
5. **ACME bootstrap vhost**：在 80 端口提供 `/.well-known/acme-challenge/`，nginx 常驻。
6. **证书**：`certbot certonly --webroot` 申请**单张同时覆盖两个域名的证书**
   （lineage 名 `observatory`）。随后：
   * `openssl -checkhost` 断言证书包含两个域名；
   * `-checkend 86400` 断言 24h 内不过期；
   * 用 `install` **实体拷贝**到 `$APP_DIR/certs/server.crt|server.key`（不再用符号链接），
     属主改为 `OBS_UID`、私钥 600 —— 非 root 容器必须能读。
7. **nginx 站点**：渲染 `deploy/nginx/*.conf.template` → 两个站点，安装
   `observatory-map.conf` 到 `conf.d`（WebSocket map 只能定义一次），移除 ACME bootstrap 与
   `sites-enabled/default`，`nginx -t` 通过才 reload。
8. **构建启动**：`OBS_IMAGE_TAG=$(cat VERSION)` 构建/启动；120 秒内健康检查失败或运行版本 ≠ VERSION
   都会 **退出非 0**（旧版会打印“部署完成”）。

成功输出包含控制台 URL、受控端双域名、证书路径、版本与后续步骤（上传安装包、续期 cron、体检）。

## 3. 网络拓扑

```
浏览器/受控端 → 443 nginx（双域名分流）→ https://127.0.0.1:8443（容器 TLS）
             → uvicorn → 应用层 HostSplit → 路由
```

* **单容器**：`observatory-api`，非 root（UID 10001）、只读根文件系统、`/data` 与 `/tmp` 可写、
  `cap_drop: ALL`、`no-new-privileges`、内存/CPU/PID 限额，全部可在 `server/.env` 调整。
* **数据卷**：`observatory-data:/data`，含 `observatory.db`、`frames/ thumbs/ packages/ staging/ tmp/ webui/`。
* **证书卷**：`../certs:/certs:ro`（实体文件）。
* **端口**：仅 8443，默认 `127.0.0.1:8443`；只有 CDN/上游代理直连时才设 `OBS_BIND_ADDR=0.0.0.0`。
* **域名分工**（nginx + 应用层 HostSplit 双层）：

| 路径 | control.tianhw.top | observatory.123423.xyz |
| --- | --- | --- |
| `/`、`/assets/*`、后台 API、控制台 WS | ✅ | ❌ 404（提示控制台域名） |
| `/api/v1/agent/*`（含 v3 `/agent/link`、旧 `/agent/ws`） | ✅ | ✅ |
| `/api/v1/public/*`、`/api/v1/health`、`/api/v1/version` | ✅ | ✅（受控端域名另把旧链 `/install.ps1` 内部改写到 public） |

## 4. 日常更新（可回滚）

```bash
sudo bash deploy/update.sh
```

流程：

0. **先跑预检**（幂等、不构建、不换镜像）：
   ```bash
   sudo bash deploy/update.sh --preflight
   ```
   它会校正数据卷与 `/certs` 属主、打印 compose 状态并请求
   `https://127.0.0.1:8443/api/v1/health`；预检失败不要继续升级。
1. 记录升级前状态到 `backups/upgrade-<时间戳>/`：`old commit`、`VERSION`、运行中镜像 ID、
   `server/.env` 指纹。
2. **自动备份**数据库 + 数据卷 + 证书（调用 `deploy/backup.sh`）。备份失败 **直接中止，不改任何东西**；
   `SKIP_BACKUP=1` 可跳过（不推荐）。升级全过程写入 `backups/update.log`，用 `flock`
   阻止并发执行。
3. 有未提交改动先 `git stash`；`git pull --ff-only`；脚本自身被 pull 更新时自动 re-exec 一次
   （旧状态与备份记录通过环境变量沿用，不会把新 commit 当成旧版本）。
4. 以 `OBS_IMAGE_TAG=<VERSION>` 构建镜像（同时维护 `observatory/api:latest`）。启动前
   **强制校正数据卷与证书属主**（0.3.0 镜像以非 root UID 运行）；校正失败直接回滚，
   不会留下 crash loop。`up -d` 后先确认容器处于 `running`（不是 `restarting/exited`），
   再等健康检查。
5. 健康检查 120s，且 `/api/v1/version` 必须等于 `VERSION`；**任一失败自动回滚**：
   `git reset --hard <旧 commit>` + 用旧镜像 ID 打 `rollback-<戳>` tag 并 `up -d --no-build`，
   随后退出非 0。
6. 成功后只登记与 `VERSION` 一致的受控端 zip（`agent/dist/observatory-agent-<VERSION>.zip`），
   其它版本的 zip 会被跳过并告警；本地没有该包时尝试 `deploy/fetch-agent-package.sh` 从 CI 的
   `agent-dist` 分支取回（仍会校验分支 `VERSION` 与 `SHA256SUMS`）。

回滚边界：

| 组件 | 自动回退 | 说明 |
| --- | --- | --- |
| 代码 | ✅ `git reset --hard` 旧 commit | 未跟踪文件不会删除；stash 需手工 `git stash pop` |
| 镜像 | ✅ 旧镜像 ID 重新打 tag 启动 | 若旧镜像已被清理则只能重建 |
| 数据库 | ❌（有备份，人工恢复） | 迁移是加列/加表型，旧镜像通常可直接跑新库；确需恢复用 `deploy/restore.sh` |
| 证书 | 不动 | 证书问题看第 5 节 |
| nginx | 不动 | 站点模板变更需再跑 `deploy/setup.sh` |

## 5. 证书与续期

* 申请与续期都走 **webroot**（`--webroot -w /var/www/certbot`），nginx 常驻 80，不再 `--standalone`
  （旧方案续期时 80 被 nginx 占用，必然失败）。
* 续期命令（cron 建议每天一次）：

```bash
sudo bash deploy/renew-certs.sh
# cron:
0 4 * * * root bash /opt/observatory/deploy/renew-certs.sh >/dev/null 2>&1
```

  * 只续期 `CERT_NAME` 这一个 lineage（`certbot renew --cert-name observatory`），
    旧域名 lineage 不会让 cron 失败；
  * 续期**失败退出非 0**（可用于监控告警），不再吞错；
  * 证书真的变化时才重新实体拷贝到 `certs/` 并 `docker compose restart api`；
  * 副本丢失时会自动补齐；剩余 <14 天打印告警。
* 手工验证：

```bash
ls -l /opt/observatory/certs            # 应为普通文件（-rw-r--r-- / -rw-------），不是 l 链接
sudo openssl x509 -in /opt/observatory/certs/server.crt -noout -dates -checkhost control.tianhw.top
sudo openssl x509 -in /opt/observatory/certs/server.crt -noout -checkhost observatory.123423.xyz
docker exec observatory-api openssl x509 -in /certs/server.crt -noout -dates
```

* 旧主机迁移注意：0.3.0 统一使用 lineage `observatory`（可用 `CERT_NAME` 覆盖）。如果
  `/etc/letsencrypt/renewal/` 里还残留旧域名 lineage（例如旧版按域名分别申请的证书），
  `certbot renew` 可能仍按旧认证器（standalone）续期并让 cron 失败。迁移后执行
  `sudo certbot certificates` 检查，确认后 `sudo certbot delete --cert-name <旧 lineage>`
  删除旧证书，再跑一次 `deploy/setup.sh`。

## 6. 备份与恢复

```bash
sudo bash deploy/backup.sh [目标目录]          # 默认 /opt/observatory/backups
sudo bash deploy/restore.sh <data.tar.gz> [observatory-db-*.db] [--yes]
```

备份产物（`umask 077`，目录 700）：

| 产物 | 内容 |
| --- | --- |
| `observatory-db-<戳>.db` | 容器内 SQLite backup API 生成的**一致性**数据库快照 |
| `observatory-data-<戳>.tar.gz` | 整个 `observatory-data` 卷（画面/缩略图/安装包/前端） |
| `observatory-certs-<戳>.tar.gz` | `/etc/letsencrypt`（含私钥，权限 600） |
| `manifest-<戳>.txt` | 时间、主机、各文件 sha256 |

保留 7 天（`find -mtime +7`）。建议异地/对象存储保存一份；备份包含屏幕画面，按敏感数据管理。

恢复行为：

1. 容器仍运行时先自动做一次“恢复前备份”（`backups/pre-restore-<戳>`）；
2. 解包到临时目录并校验：必须含 `observatory.db`；有 `python3` 时执行
   `PRAGMA integrity_check`，失败**拒绝覆盖**；
3. 停止容器 → 清空数据卷（含隐藏文件）→ 写入归档 → `chown -R $OBS_UID`（非 root 容器必需）；
4. 启动并等待健康检查，失败退出非 0。

证书不自动恢复：`tar xzf observatory-certs-*.tar.gz -C /etc` 后运行 `deploy/setup.sh`
（重新实体拷贝 + 断言）或 `deploy/renew-certs.sh`。

### 从 0.2.x 旧卷升级到非 root 容器

0.2.x 的数据卷属主是 root。升级到 0.3.0 前执行一次：

```bash
docker run --rm -v observatory-data:/data alpine chown -R 10001:10001 /data
```

否则容器（UID 10001）无法写 SQLite/画面。`restore.sh` 已自动做 chown。

## 7. 安装链路与一次性安装令牌

控制台「设置 → 安装程序」会生成**一次性安装令牌**并渲染安装程序：

* 令牌默认有效期由**控制台设置** `install_token_ttl_minutes` 决定（默认 1440 分钟 =
  24 小时；建议按现场调到 30–60 分钟），签发接口也可用 `ttl_s`（60..86400 秒）覆盖；
  **单次使用**、首次注册时绑定设备；
* 下载的 `Observatory-Install-<版本>.cmd` 内置令牌而不是长期共享注册码（A18）；
* 令牌过期/被使用 → 安装报 401/403，重新生成即可；撤销方式：控制台删除令牌，
  或把 `OBS_ENROLL_CODE` 置空（仅影响旧共享注册码路径）。

安装流程（不变，只换凭据）：

1. 双击 `.cmd`（或 `irm …/install.ps1?token=… | iex`）；
2. 非管理员 → 只弹**一次** UAC；提权子进程重新下载脚本；
3. 查询 `/api/v1/public/agent/latest` → 下载 zip → 校验 sha256 → 解压到
   `C:\Program Files\Observatory` → `--install-token` 注册服务并启动；
4. 之后自动更新/远程控制/远程卸载全部在 SYSTEM 服务内完成，不再弹 UAC。

`usb-installer/` 是现场向导：不内置任何凭据，现场输入服务器地址 + 令牌（或旧注册码）。

## 8. 配置项

全部以 `OBS_` 开头，写在 `server/.env`（模板见 `server/.env.example`）。
`server/.env.dev` **只用于本地开发**，0.3.0 起生产应拒绝/告警这些弱口令（代码侧契约）。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `OBS_SECRET_KEY` | 必填 | JWT 与设备令牌哈希密钥；更换后所有会话失效 |
| `OBS_ADMIN_PASSWORD` | 必填 | 初始管理员密码（改过以后以数据库哈希为准） |
| `OBS_ENROLL_CODE` | 空=禁用 | 旧版共享注册码（0.2.x 兼容） |
| `OBS_DATA_DIR` | `/data` | 数据目录 |
| `OBS_CONSOLE_HOST` | `control.tianhw.top` | 唯一允许控制台的域名 |
| `OBS_AGENT_HOSTS` | 两个域名 | 允许受控端接口的域名 |
| `OBS_PUBLIC_BASE_URLS` | 两个 https | 下发给受控端的地址列表 |
| `OBS_BIND_ADDR` | `127.0.0.1` | compose 端口绑定（A11） |
| `OBS_PORT` | `8443` | 宿主机端口 |
| `OBS_TRUST_FORWARDED_FOR` | `false`（代码）/脚本置 `true` | 仅可信反代拓扑开启 |
| `OBS_UID` | `10001` | 容器运行 UID |
| `OBS_MEM_LIMIT` / `OBS_CPUS` / `OBS_PIDS_LIMIT` | `1g` / `2.0` / `256` | 容器资源限制 |
| `OBS_SESSION_TTL_MINUTES` | 720 | 控制台会话有效期 |
| `OBS_AGENT_OFFLINE_AFTER_S` | 120 | 离线阈值（0.3.0 起真实生效） |

> 安装令牌 TTL 不是环境变量：它是控制台设置 `install_token_ttl_minutes`
> （默认 1440 分钟），签发时可用 `ttl_s` 覆盖。

业务参数（采集间隔、保留天数、配额、归档等）在控制台「设置」页修改，不需要重启。

默认保留策略（以代码为准）：画面 **14 天**、审计 **180 天**、命令 **30 天**。

## 9. 云主机迁移 / 0.2.x 迁移

```bash
sudo bash deploy/migrate-from-legacy.sh   # 旧 shenmi 栈 → Observatory 0.3.0
```

会：配置部署密钥 → 拉取 `main`（已有仓库 `reset --hard origin/main`）→ 实体拷贝旧证书并 chown
→ 复用旧 `SECRET_KEY/ADMIN_PASSWORD`、生成新注册码与 compose 变量 → 停旧容器（旧数据原样保留）
→ 构建启动并健康检查（失败退出非 0）→ 提示再跑 `setup.sh` 渲染 0.3.0 nginx 模板。

回滚旧栈：`docker compose -p shenmi -f /opt/shenmi/docker-compose.yml up -d`。

## 10. 故障排查

```bash
docker compose -f deploy/docker-compose.yml --env-file server/.env ps
docker compose -f deploy/docker-compose.yml --env-file server/.env logs -f --tail=100
docker exec -it observatory-api python -m observatory.cli version
curl -sk https://127.0.0.1:8443/api/v1/health
curl -sk https://control.tianhw.top/api/v1/health
curl -sk https://observatory.123423.xyz/api/v1/health
sudo nginx -t && sudo systemctl reload nginx
```

常见问题：

* **容器起不来，日志报读不到证书**：`certs/` 是实体文件吗？属主是 `OBS_UID` 吗？
  `ls -l /opt/observatory/certs`；`docker exec observatory-api ls -l /certs`。
* **控制台 502/健康检查失败**：先看 `docker compose logs`；8443 未被监听或证书过期都会这样。
* **521 / 522（CDN 提示源站不可达，浏览器显示 `521 No Reason Phrase`）**：
  这不是应用返回的 HTTP 状态，而是 CDN（Cloudflare/EdgeOne 等）**连不上源站**。
  先按层定位，不要先动 DNS：
  ```bash
  # 1) 源站本机：nginx 与容器是否都在
  ss -ltnp | grep -E ':(80|443|8443)\b'
  curl -sk https://127.0.0.1:8443/api/v1/health
  docker ps -a --filter name=observatory-api
  # 2) 源站直连 443（绕过 CDN）
  curl -skI --resolve control.tianhw.top:443:127.0.0.1 https://control.tianhw.top/api/v1/health
  # 3) 最近是否有 upstream 拒绝/重启
  tail -50 /www/wwwlogs/observatory.123423.xyz.error.log 2>/dev/null \
    || tail -50 /var/log/nginx/observatory-console.error.log
  docker logs --since 30m observatory-api 2>&1 | tail -50
  ```
  常见根因（本仓库 2026-10-24 的真实事故）：
  * **0.3.0 镜像以非 root（10001）运行，但数据卷/证书仍是 root 属主**：容器 `exit 1`
    反复重启，nginx 对 `127.0.0.1:8443` 报 `connect() failed (111: Connection refused)`，
    CDN 因此返回 521。修复：
    ```bash
    docker run --rm -v observatory-data:/data alpine:3 chown -R 10001:10001 /data
    chown 10001:10001 /opt/observatory/certs/server.crt /opt/observatory/certs/server.key
    docker compose -f deploy/docker-compose.yml --env-file server/.env up -d
    ```
    `deploy/update.sh` 现在会在启动前强制校正属主，失败直接回滚，并用
    `flock` 阻止并发升级；不再出现“脚本说成功、容器在 crash loop”。
  * 源站 nginx 自身没起来：`systemctl status nginx`（宝塔面板是
    `/etc/init.d/nginx status`）→ `nginx -t` → `systemctl reload nginx`。
  * 安全组/防火墙只放行了部分 CDN 回源 IP：确认 80/443 对 CDN 回源段开放；
    本机 `ufw status` / 云厂商安全组都要看。
  * CDN 回源端口配错（例如指向 8443 但证书/协议不匹配）：回源必须是源站 443。
  排查时优先看**源站 access/error log 有没有收到 CDN 请求**：有请求→应用/上游问题；
  没请求→网络/防火墙/CDN 回源配置问题。

* **容器一直 restart，提示 permission denied 写 /data**：数据卷属主还是 root；
  执行第 6 节的 `chown -R 10001:10001 /data`。
* **安装报 401/403**：令牌过期/已使用/域名不对；重新生成令牌。旧共享注册码需与 `.env` 一致。
* **控制台能开但接口 404**：访问了受控端域名；控制台只认 `control.tianhw.top`。
* **设备一直“受限”**：WebSocket 被中间设备阻断；检查 nginx `Upgrade`/`Connection` 与 CDN。
* **更新后服务没起来**：`deploy/update.sh` 已自动回退；看 `backups/upgrade-*/result.env`、
  `upgrade.env`；需要恢复数据时用同目录 `backup/` 执行 `restore.sh`。
* **证书剩余天数告警**：检查 80 端口是否可达、`/var/www/certbot` 是否有权限、DNS 是否变更。
