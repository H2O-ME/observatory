# 受控端打包

受控端是一个 PyInstaller **onedir** 程序（不是 onefile）：更新时需要原子替换目录，
onedir 的启动速度也更快，且不需要每次解压。

产物命名固定：`observatory-agent-<版本>.zip`，版本号取自仓库根目录 `VERSION`。

## 1. 在 Windows 上构建（开发机 / 现场机）

```powershell
git clone <repo> observatory
cd observatory
pwsh -File agent/build/build.ps1
```

脚本会：建 venv → 装依赖 → 读 `VERSION` → PyInstaller → 在 exe 旁写 `VERSION` 文件 →
打包成 `agent/dist/observatory-agent-<版本>.zip`。

单独调试时：

```powershell
cd agent
pip install -r requirements.txt
python -m observatory_agent --doctor     # 检查权限、会话、通道
python -m observatory_agent --console    # 前台运行看日志
python -m observatory_agent --version
```

## 2. 在 CI 上构建（推荐）

`.github/workflows/build.yml` 的 `agent` 任务在 `windows-latest` 上构建，产出 zip 作为 artifact；
打 `v*` 标签时同时发布到 GitHub Release。

发版流程：

```bash
python tools/set_version.py --bump       # 0.2.0 -> 0.2.1，同步服务端/受控端/前端
git commit -am "0.2.1"
git tag v0.2.1
git push && git push --tags
cd /opt/observatory && sudo bash deploy/update.sh
```

`update.sh` 拉代码、重建镜像，并把仓库里新的 `agent/dist/*.zip` 登记为可更新版本。
没有本地 zip 时，用 `deploy/build-agent.sh --from-release v0.2.1` 直接从 Release 取。

## 3. 在 Linux 服务器上构建（可选）

```bash
sudo bash deploy/build-agent.sh
```

用 Wine 跑 Windows 版 Python + PyInstaller。可行，但对 Wine 版本敏感；脚本会明确报错
而不是产出坏包。拿不到可靠结果时就用 `--from-release`。

## 4. 自动更新是怎么做到的

1. 受控端每 20 秒心跳，服务端在响应里带上 `update: {version, url, sha256, size_bytes}`（仅当有更新）
2. 受控端下载到 `%ProgramData%\Observatory\updates\<version>\`，校验 SHA-256
3. 写入 `pending.json`，然后向服务控制器发"停止"请求（服务已停止才能替换正在运行的 exe）
4. 一个独立的小助手进程（与正在运行的 exe 不同路径，避免文件占用）：
   备份当前版本目录 → 用新目录替换 → 写 `current.json` → 重启服务
5. 新版本启动失败时，助手会在 60 秒内回滚到备份目录
6. 成功后清理旧版本目录与备份

关键点：**全程以 SYSTEM 运行，不弹 UAC，不需要重新安装**。安装时的 UAC 是唯一一次。

## 5. 远程卸载是怎么做到不弹 UAC 的

卸载同样由受控端服务自己完成（`agent/observatory_agent/uninstall.py`）：

1. 服务收到 `uninstall` 命令 → 写标记 → 启动独立清理进程 → 服务停止
2. 清理进程以 SYSTEM 权限：停止/删除服务、删除安装目录（自身 exe 走
   `MoveFileEx(..., MOVEFILE_DELAY_UNTIL_REBOOT)` 延迟删除）、删除防火墙规则、
   清理注册表与服务恢复项、删除计划任务
3. 删除前调用 `/api/v1/agent/uninstall/ack`，服务器标记为"已卸载"
4. 删除 `%ProgramData%\Observatory`

没有提权环节，所以不会弹窗。旧版本把这步放在"再运行一次安装器 --uninstall"，那需要 UAC，
无人值守的机器就永远卸载不掉——0.2.0 彻底改掉了。

## 6. 受控端内部结构

```
service.py       Windows 服务框架（SYSTEM，持有网络）
runner.py        主循环：传输阶梯、心跳、帧上传、更新、卸载判定
transport.py     WsChannel（含探测）/ PollChannel
worker.py        每个用户会话一个：命名管道、采集、输入、文件操作
capture.py       mss 采集 + 变化检测 + WebP
input.py         SendInput（鼠标/键盘/滚轮/Unicode）
fs_ops.py        文件系统操作（含分片读写）
pipe_server.py   \\.\pipe\observatory-agent-<会话> 服务端
```

服务与用户会话必须分开：桌面采集和输入注入只能在交互式会话里，而自动更新与卸载必须
在没有用户登录时也能工作。两者通过命名管道通讯，用 `PeekNamedPipe` 轮询避免同步读阻塞。

## 7. 常见打包问题

| 现象 | 原因与处理 |
| --- | --- |
| 启动即退出，`--doctor` 报未安装服务 | 需要管理员权限运行安装（`--install`） |
| 采集全是黑屏 | 会话 0 隔离：确认有用户登录，且 worker 在用户会话内 |
| 输入无效 | 目标程序以更高完整性运行（例如以管理员启动的任务管理器），或 UIPI 阻止 |
| 更新后仍显示旧版本 | 检查 `%ProgramData%\Observatory\current.json` 与回滚日志 |
| 打包体积过大 | 确认 spec 里 `upx=False`；UPX 会让杀软误报概率大增 |

## 8. 签名（建议）

未签名的 exe 在部分环境会被 SmartScreen 拦截。生产部署建议用代码签名证书签名：

```powershell
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /a observatory-agent.exe
```

签名要在 PyInstaller 之后、打包 zip 之前做。
