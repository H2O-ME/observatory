# 受控端打包（Observatory 0.3.7）

受控端是 PyInstaller **onedir** 程序（不是 onefile）：自动更新需要整目录原子替换，onedir 启动也更快。
产物命名固定：`observatory-agent-<版本>.zip`，版本号取自仓库根 `VERSION`（唯一来源）。

## 1. 0.3.0 的受控端结构

```
agent/observatory_agent/
  main.py            # service / worker / update-helper / purge-helper / --version / --doctor
  version.py         # 与仓库根 VERSION 同步的版本号
  core/
    envelope.py      # 与服务端同构的协议信封（独立复制，避免跨包依赖）
    link.py          # ★ 唯一链路：同一信封，ws 与 http 两个载体自动选优
    outbox.py        # 有界 spool：至少一次 + 幂等 id（替代 0.2.x 的 spool 实现）
    runtime.py       # 运行生命周期：注册、心跳/命令分发、链路装配（懒加载 win/tasks）
    commands.py      # 命令执行与结果回传
    sysinfo.py       # 系统信息采集
    config.py        # 配置 + device_time_offset
    logging.py
  win/
    service.py       # SCM 生命周期 + failure actions
    session.py       # WTS 会话发现 + CreateProcessAsUser
    pipe.py          # 服务↔worker 单一信封管道
  tasks/
    capture.py       # 唯一 CaptureEngine（worker 内唯一实现）
    input.py         # SendInput + 虚拟桌面坐标 + DPI 感知
    fs.py            # 12 种文件操作 + 分片
    update.py        # 唯一更新路径：verify→stage→precheck→swap→rollback
    uninstall.py     # 整目录 staging（修复 onedir）；ack 在 helper 确认后
```

进程模型不变：**1 个服务进程（SYSTEM）+ 每个可采集会话 1 个 worker + 临时 update/uninstall helper**。
采集与输入注入只能发生在用户会话；更新与卸载必须在无登录时也能工作——这是双进程架构的真正理由。

## 2. 在 Windows 上构建（开发机 / 现场机）

```powershell
git clone <repo> observatory
cd observatory
pwsh -File agent/build/build.ps1
```

脚本会：选择 Python（优先仓库 `.venv`，否则 `python`）→ 校验 `VERSION` 是 semver →
装 `agent/requirements.txt` + PyInstaller → 读 spec 构建 onedir → 在产物目录写 `VERSION` →
生成 `agent/dist/observatory-agent-<版本>.zip`（zip 根即安装根）。

PyInstaller 入口固定为 `agent/build/entry.py`，spec 文件是 `agent/build/observatory-agent.spec`。
0.3.0 的 `hiddenimports` 显式列出 `observatory_agent.core.runtime`、`win.service/session/pipe`、
`tasks.capture/input/fs/update/uninstall`：这些都在 `runtime.py` 里按需懒加载，静态分析看不到，
新增运行期懒加载模块时必须同步补进 spec，否则打包后会在目标机上 `ModuleNotFoundError`。

单独调试：

```powershell
cd agent
pip install -r requirements.txt
python -m observatory_agent --doctor     # 检查权限、会话、链路
python -m observatory_agent --console    # 前台运行看日志
python -m observatory_agent --version
```

签名（建议）：`-SignThumbprint <证书指纹>` 会在 PyInstaller 之后、打包 zip 之前调用 signtool
（CI 默认不签名，SmartScreen 可能拦截未签名 exe）。

## 3. 在 CI 上构建（推荐）

工作流在 **`.github/workflows/ci-cd.yml`**。受控端 exe 仅在 `agent/**` 或 `VERSION`
变更时才动用 Windows runner（2 倍费率），产物挂固定 Release `latest-agent`；
上线时 `deploy/pull-and-restart.sh` 自行下载并登记进控制台：

| job | 内容 |
| --- | --- |
| `changes` | paths-filter：判断 `agent/**` / `VERSION` 是否变更 |
| `build-agent` | **windows-latest**：装 agent 依赖 → `pwsh -File agent/build/build.ps1` → 产物挂 Release `latest-agent` |
| `build-server` | ubuntu：构建前后端一体镜像 → `ghcr.io/h2o-me/observatory:<sha>`（tag 推送时额外打 `vX.Y.Z` 别名） |
| `deploy-hk` | SSH 触发服务器 `deploy/pull-and-restart.sh <sha> <agent_changed>`，健康失败自动回滚 |

质量门禁（pytest / `pnpm typecheck` / `pnpm build` / `pnpm check:legacy`）在本地跑，
CI 不再跑测试。

## 4. 发版流程

0.3.6 起为自动链路，本地只需要 push：

```bash
python tools/set_version.py --bump       # 例：0.3.6 -> 0.3.7，同步服务端/受控端/前端副本
git commit -am "release: 0.3.7"
git push origin main                     # 服务器 ≤2 分钟自动拉取并部署服务端/WebUI
git tag -a v0.3.7 -m "Observatory 0.3.7"
git push origin v0.3.7                   # CI 构建受控端 → 强推 agent-dist

# 观察（服务器）：
tail -f /var/log/observatory-auto-update.log
```

- `agent-windows` 会等全部质量门禁通过后才构建；只有 tag 会推 `agent-dist`（防止 main 的任意推送
  替换全员受控端）。
- 服务器自动发现同版本 `agent-dist` 后执行 `deploy/fetch-agent-package.sh`：导出 zip 到
  `/data/tmp`、校验 `SHA256SUMS`、`package-add` 落库；低于该版本的在线设备在下次心跳收到更新。
- 手工兜底：`sudo bash deploy/fetch-agent-package.sh`；没有 CI 产物时可
  `deploy/build-agent.sh --from-release v0.3.7`（需 gh/凭据）。
- 完整发布/更新链路见 [`docs/发布与更新链路.md`](发布与更新链路.md)。

## 5. 自动更新怎么做到不弹 UAC

1. 受控端心跳拿到 `update: {version, url, sha256, size_bytes}`（仅当有更新且本机版本可自升级）；
2. 下载到 `%ProgramData%\Observatory\updates\<version>\`，**流式 sha256 校验**；
3. 预检：新 exe 能否启动（`--version`）；
4. 写入 `pending.json` → 向服务控制器请求停止服务；
5. 独立 helper 进程（与运行中的 exe 不同路径）整目录 staging → 替换 → 写 `current.json` → 重启服务；
6. 新版本起不来时 helper 在窗口期内回滚到备份目录；
7. 成功后清理旧版本与备份。

全程 SYSTEM，不弹 UAC。强制更新（远程命令）同样要求 sha256；缺摘要会被服务端拒绝（0.3.0 修复）。

## 6. 远程卸载怎么做到不弹 UAC

1. 服务收到 `uninstall` 命令 → 写标记 → 启动独立清理进程 → 服务停止；
2. 清理进程以 SYSTEM 权限：停止/删除服务、删除安装目录（自身 exe 用
   `MoveFileEx(..., MOVEFILE_DELAY_UNTIL_REBOOT)` 延迟删除）、删除防火墙规则、
   清理注册表与服务恢复项、删除计划任务；
3. **helper 确认存活后**才通过链路上报 `uninstall_ack` 信封消息（服务端据此标记
   `uninstalled_at_ms`）；helper 起不来则保持在线并上报
   `uninstall_failed`（0.3.0 修复：不再“ack 了但其实没删”）；
4. 删除 `%ProgramData%\Observatory`。

## 7. 常见打包问题

| 现象 | 原因与处理 |
| --- | --- |
| 启动即退出，`--doctor` 报未安装服务 | 需要管理员安装（`--install` / 安装脚本） |
| 采集全是黑屏 | 会话 0 隔离：确认有用户登录，且 worker 在用户会话内 |
| 输入无效 | 目标程序以更高完整性运行（如管理员启动的任务管理器），或 UIPI 阻止 |
| 更新后仍显示旧版本 | 检查 `%ProgramData%\Observatory\current.json` 与回滚日志 |
| 打包体积过大 | 确认 spec 里 `upx=False`；UPX 会显著增加杀软误报 |
| 安装报 401/403 | 一次性安装令牌过期/已使用/域名不符；重新生成令牌 |

`WS /agent/ws` 等）已全部 404，0.2.x 受控端必须升级到 0.3.x 才能接入（数据库结构迁移
`test_legacy_db_schema` 仍保留，0.2.10 的数据库可直接迁移）。
新受控端只走协议 v3（`/api/v1/agent/link` + `/api/v1/agent/frames`）。
