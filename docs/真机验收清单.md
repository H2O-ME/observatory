## 1. ACL 是否真的生效，并且用户 worker 还能干活

审计 R01/A2：把配置和令牌限到 SYSTEM+Administrators 之后，用**用户令牌**启的
worker 可能读不到配置、写不了日志。代码已改成「worker 不读配置文件、日志另放」，
但 `icacls` 是否真的落地、受限令牌下是否真的能写，只有真机能证明。

### 1.1 看权限

```powershell
icacls C:\ProgramData\Observatory
icacls C:\ProgramData\Observatory\config.json
```

**期望**：

- 目录与 `config.json` 的访问列表里**只有** `NT AUTHORITY\SYSTEM` 与
  `BUILTIN\Administrators`（以及继承来的 `TrustedInstaller` 之类系统项）；
- **不应**出现当前登录用户名或 `Users` 组；
- `config.json` 不应有 `(I)` 继承来的普通用户读权限。

### 1.2 普通用户确实读不到令牌

在**非管理员**窗口：

```powershell
Get-Content C:\ProgramData\Observatory\config.json
```

**期望**：`拒绝访问` / `Access is denied`。**能读出来就是没通过**（令牌泄露面）。

### 1.3 worker 确实还活着

让测试机保持有人登录的桌面状态（worker 只在已登录会话里跑），等 60 秒后：

```powershell
Get-Process | Where-Object { $_.Name -like 'observatory*' } |
  Select-Object Name, Id, SessionId, @{n='User';e={ (Get-CimInstance Win32_Process -Filter "ProcessId=$($_.Id)").GetOwner().User }}
```

**期望**：除了 SYSTEM 身份的 `observatory-agent`，还有**一个当前登录用户身份**的
worker 进程（SessionId 与桌面会话一致）。

### 1.4 worker 日志可写、能看到

```powershell
Get-ChildItem $env:LOCALAPPDATA\Observatory\logs | Select-Object Name, Length, LastWriteTime
Get-Content (Get-ChildItem $env:LOCALAPPDATA\Observatory\logs\*.log | Sort-Object LastWriteTime -Desc | Select-Object -First 1).FullName -Tail 20
```

**期望**：日志目录存在于**用户**的 `%LOCALAPPDATA%`（不是 ProgramData），文件在
增长，末尾没有 `PermissionError` / `拒绝访问` / `Traceback`。

### 1.5 服务端日志里没有权限报错

```powershell
Get-Content C:\ProgramData\Observatory\logs\*.log -Tail 200 | Select-String -Pattern 'PermissionError|拒绝访问|Access is denied|Traceback'
```

**期望**：无输出。（服务端日志路径若不存在，以实际安装目录为准。）

## 2. 控制会话：TTL、会话校验、按键是否真的松开

审计 R02/R03/A3：以前服务端下发 `ttl_s` 但受控端丢弃，断链或 stop 丢失后可能一直
采着；已按下的键也没有账本。现在有本地单调时钟租约 + 统一清理。**卡键只能真机试**。

### 2.1 正常控制 + 无 UAC

1. 控制台打开该设备「实时画面」，点开始控制。
2. 在画面里：打字、按住 `Ctrl` 组合键、拖拽鼠标、滚轮上下滚。

**期望**：画面在 1~2 秒内动起来；输入生效；**全程没有任何 UAC 弹窗**。

### 2.2 失焦必须松开修饰键（这一条最容易复现卡键）

1. 在控制区域里**按住 `Ctrl` 不放**（不要松开）。
2. 鼠标移出画面，点击浏览器地址栏（或直接 `Alt+Tab` 切窗口）。
3. 回到控制区域，**正常单击一次**（不要按 Ctrl）打几个字母。

**期望**：打出来的是**普通字母**，不是 Ctrl 组合键效果（比如 `Ctrl+A` 全选、
`Ctrl+C` 复制）。如果字母变成了组合键行为 → **卡键没修好**。

> 用记事本验证最直观：在远程桌面里开记事本，按住 Ctrl 失焦再回来按 `a`，
> 期望出现字母 `a`，而不是全选。

### 2.3 停止必须松开所有键

1. 按住 `Shift` 和鼠标左键（保持按下）。
2. 点控制台「停止控制」。

**期望**：远程没有残留"按住 Shift / 按住左键"的状态；随后正常点击一次不出现
框选或连续选择。

### 2.4 断链兜底

1. 建立控制中，按住 `Alt`。
2. 直接**拔网线或禁用网卡**（保持按住 Alt）。
3. 等 10 秒，恢复网络，重新进入控制。

**期望**：重连后第一次按键是正常字符，不是 Alt 组合键；控制台命令记录里能看到
控制中断的记录（`control_failed` / 控制会话结束）。

### 2.5 租约到期（本地 TTL）

1. 建立控制后，在**测试机上**把服务端地址阻断 15 分钟（或直接把测试机断网）。
2. 保持页面不要手动停止，等超过服务端下发 TTL（默认 600 秒）。

**期望**：到期后受控端**停止采集/转发**（控制台上画面停止更新），而不是继续传；
恢复网络后控制台显示会话已结束，需要重新点开始。

> 说明：这条验证的是"本地兜底"，服务端本身也会撤销授权。两者都生效才对。

## 3. UAC 提权流程（安装脚本参数是否原样传递）

审计 R06/R07/A5：提权分支以前会丢掉 `-Uninstall` 和自定义 `-BaseUrls`，导致
"以普通用户请求卸载，结果进入安装流程"。另外离线包以前被强制联网探测。

### 3.1 普通用户请求卸载 → 仍然是卸载

在**非管理员**窗口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -Uninstall
```

**期望**：弹**一次** UAC；点是之后**走卸载**（出现"已卸载"字样、服务被移除），
**不是**重新安装。装完记得重新装回来，否则后面几项没法测。

```powershell
Get-Service ObservatoryAgent   # 期望：找不到该服务
Test-Path 'C:\Program Files\Observatory'   # 期望：False
```

### 3.2 自定义服务器地址要保留

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -BaseUrls 'https://control.tianhw.top'
```

**期望**：提权后 banner 里「服务器」显示的是你传的地址，而不是脚本内置默认列表；
装完后 `config.json` 的 `base_urls` 第一项就是它。

### 3.3 离线安装真的不联网

1. 用 `python tools/build_usb_package.py --dest E:\Observatory-USB` 生成 U 盘包
   （或在已有包目录里放好 `agent-<版本>.zip`）。
2. **禁用网卡**，确认 `ping control.tianhw.top` 失败。
3. 双击 `一键安装.cmd` 或跑：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\usb-install.ps1
```

**期望**：能一路装到「安装包已解压/已安装」，**不会**在"无法连接服务器"处中止
（联网只用于最后注册，注册失败会提示"稍后重试"而不是安装失败）。

## 4. 真实重启 / 关机与 SCM recovery

审计 R05/A6：以前重启、关机是"先回成功，后台再执行，失败只写日志"。现在要求
至少一个提交机制登记成功才回 ok，关机用 `shutdown.exe` 真实退出码回执。

### 4.1 重启服务（不是重启机器）

控制台对该设备执行「重启受控端」，然后：

```powershell
Get-Service ObservatoryAgent | Select-Object Status, StartType
# 期望：Running；StartType 是 Automatic
Get-Process observatory-agent | Select-Object Id, StartTime
# 期望：StartTime 是刚才（进程真的换了），不是几小时前
```

**期望**：控制台命令状态最终是 `ok`，且设备在 60 秒内重新上线。

### 4.2 重启机器

1. 控制台执行「重启计算机」。
2. **记录命令最终状态**，然后等机器自己起来。

**期望**：命令状态为 `ok` 且带真实回执；机器确实重启；重启后服务自动起来、
设备自动上线（不需要人工登录）。若 `shutdown.exe` 被策略拦截，命令应为
`error` 并带错误详情，**不能**显示成功。

### 4.3 关机

同 4.2，执行「关机」。

**期望**：机器真的关机；命令状态 `ok`。若失败必须报错，不能假成功。

## 5. 命名管道：大文件完整性与双向哈希

审计 A3/A1：管道头部限 64 KiB，但文件分片是 1 MiB。现在大消息的 body 走管道
二进制载荷。**这条必须比对哈希**，只看"没报错"不算通过。

### 5.1 上传（测试机 → 控制台）

在测试机生成一个已知内容的 5 MiB 文件：

```powershell
$f = "$env:TEMP\obs-acl-test.bin"
$bytes = New-Object byte[] (5MB)
(New-Object Random(42)).NextBytes($bytes)
[IO.File]::WriteAllBytes($f, $bytes)
(Get-FileHash $f -Algorithm SHA256).Hash
```

在控制台「文件」页把这个文件**上传**到测试机（走的是同一条分片链路），然后：

```powershell
(Get-FileHash "$env:TEMP\obs-acl-test-uploaded.bin" -Algorithm SHA256).Hash
```

**期望**：两个 SHA256 **完全一致**。不一致或中途报 `PipeProtocolError` → 没通过。

### 5.2 下载（控制台 → 本地）

在控制台把测试机上一个已知文件下载到本机，比对本地哈希与控制台上显示的哈希。

**期望**：一致；下载过程无 `PipeProtocolError`、无"文件大小为 0"。

### 5.3 边界大小

分别试 **50 KiB、64 KiB、700 KiB、1 MiB、2 MiB** 各传一次。

**期望**：全部成功且哈希一致。50~64 KiB 这一带是旧实现崩溃区，必须专门试。

## 出问题怎么办

1. 先抓证据：`%TEMP%\observatory-install.log`、`%LOCALAPPDATA%\Observatory\logs\*.log`、
   `C:\ProgramData\Observatory\logs\*.log`，以及控制台该设备「命令」页的完整 JSON。
2. 服务端回滚：`/data/.pre-deploy.db` 与 `/data/backups/pre-migrate-v*.db` 都是换库前
   快照；镜像回滚用 `OBS_IMAGE_TAG=<旧 sha> docker compose up -d`。
3. 记录表里写清**实际输出**，不要只写"失败"——复现条件是修 bug 的一半。
